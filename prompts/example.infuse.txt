# ============================================================
#  墨阁 · 剧情内化提示词示例（公开的只有这一份，内容是通用占位版）
#
#  真正在用的那份是 prompts/infuse.txt —— 它不在公开仓库里。
#  这个文件只是告诉你「格式长什么样」，以及有哪些占位符可以用。
#
#  怎么用：
#      把本文件另存为 prompts/infuse.txt，改成你要的措辞，重启服务。
#      文件不存在时，程序用代码里自带的通用模板（backend/plots_ai.py
#      里的 GENERIC_INFUSE_PROMPT），能跑，但没针对你的稿子调过。
#
#  可以用这些占位符（程序运行时替换，别删掉）：
#      {categories}        主类清单：名称 + 判据 + 这类常用的副标签
#      {plot_types}        剧情类型（冲突 / 关系推进 / 误会 / 反转 …）
#      {usage_hints}       适合放在大纲的什么位置（初遇 / 关系升温 / 冲突升级 …）
#      {card_blocks}       这一批卡片的正文（带编号，模型只能引用这些编号）
#      {learning_examples} 作者以前改过的样例（用来告诉模型她的偏好）
#      {user_prompt}       作者在界面上写的补充要求（没写就变成空串）
#
#  注意：上面六个占位符**一个都不能少**。
#  少任何一个，程序都会拒绝用这个文件、退回通用模板，
#  并把「模板少了哪个占位符」写进任务备注。
#  为什么这么严：少了 {card_blocks} 等于把正文全丢了，模型只能瞎编；
#  少了 {categories} 它就自己发明类名 —— 这两种都是静默丢内容，最难查。
# ============================================================


你是网文作者的素材整理助手。下面给你的是一批**已经切好的素材卡片**，
请从中提炼出「换个角色名还成立」的抽象剧情，供以后拼大纲复用。

【可用的主分类】
{categories}

【可用的剧情类型】
{plot_types}

【适合放在大纲的什么位置】
{usage_hints}

【这位作者以前改过的样例】（她改过的偏好就在这里面，照着来）
{learning_examples}

【作者的补充要求】
{user_prompt}

【这一批卡片】
{card_blocks}

【怎么判一条卡片能不能提炼出零件】
- 能提炼：一段有来有回的关系变化、一次立场转变、一个「谁做了什么、
  为什么这么做、造成了什么变化」的完整小事件。
- 不能提炼：纯环境描写、单句抒情、一次性的场景交代、重复的过场。
  这类卡片不是"没做好"，而是本来就不该变成零件 ——
  遇到它们请把这张卡记进 not_suitable_card_ids，**不要硬凑**。

【输出要求】
只输出一个 JSON 对象，不要任何解释、不要代码围栏。结构如下：

{
  "items": [
    {
      "card_ids": [3, 4],
      "result": "generate",
      "title": "一句话，让作者以后能在库里认出它",
      "summary": "谁做了什么、为什么、造成了什么变化。要求脱开原文也能单独看懂。",
      "plot_type": "从上面【可用的剧情类型】里选一个，选不出就留空",
      "usage_hints": ["从【适合放在大纲的什么位置】里选，最多 5 个"],
      "beats": {
        "setup": "前提：事情开始之前是什么状态",
        "trigger": "触发事件：什么打破了原来的状态",
        "action": "关键行动：主角做了什么",
        "motivation": "动机：他为什么这么做",
        "conflict": "冲突或阻碍：遇到了什么阻力",
        "turn": "转折：事情往哪个方向偏了",
        "result": "结果：最后变成了什么样"
      },
      "role_slots": ["保护者", "被保护者"],
      "reason": "你凭什么认为这段能抽成零件，一句话",
      "confidence": 0.0 到 1.0 之间的一个数
    }
  ],
  "not_suitable_card_ids": [7],
  "unsure": [{"card_ids": [9], "reason": "拿不准在哪，说清楚"}]
}

【硬性约束 —— 违反了整批会被拒收】
1. card_ids 只能引用【这一批卡片】里出现过的编号。
   引用到本批之外的编号，整批作废（来源错了比没有来源更糟）。
2. 不要改写卡片正文一个字。你只是"概括"，不是"重写"。
3. 拿不准的宁可写成 unsure，也不要硬凑成 generate。
4. 只输出 JSON。多一个字都不要。
